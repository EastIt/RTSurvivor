# RTSurvivor — техническая документация

> Документ описывает **текущее состояние MVP** на момент написания (20.11.2026):
> что реализовано, как устроено внутри и почему. Код: `src/sim.h`, `src/sim.cpp`, `src/main.cpp` (всего ~690 строк).

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Жанр | Гибрид RTS (They Are Billions / Diplomacy is Not an Option) × Vampire Survivors |
| Язык / стандарт | C++20 |
| Графика | raylib 6.2 (OpenGL, 2D-режим `Camera2D`) |
| Сборка | MinGW-w64 gcc 16.2 (UCRT), `build.bat` → `bin\rts.exe` |
| Окно | 1280×720, ресайзабельно, 60 FPS |
| Самотест | `bin\rts.exe --selftest` — headless-прогон симуляции |

**Цикл игры:** день (35 с) — стройка и найм → ночь — волна врагов → экран выбора
одного из трёх случайных бустов → следующий день. Поражение — падение ратуши.

## 2. Архитектура

Проект разделён на два слоя, и это ключевое архитектурное решение:

```
┌─────────────────────────────────────────────┐
│ main.cpp — окно, ввод, рендер, HUD, UI      │  ← зависит от raylib
│   вызывает game.tick(dt) и рисует состояние │
├─────────────────────────────────────────────┤
│ sim.h / sim.cpp — чистая симуляция          │  ← НЕ зависит от raylib
│   struct Game: здания, юниты, враги, логика │     (только <vector>, <cmath>)
└─────────────────────────────────────────────┘
```

Плюги такого разделения:

- **Headless-режим**: тот же `Game::tick()` гоняется без окна (`--selftest`),
  что даёт регрессионные тесты и балансировку на CI/скриптах.
- **Детерминизм**: с фиксированным `srand(seed)` прогон воспроизводим.
- **Портативность логики**: симуляцию можно вынести на сервер, в тесты или бота.

### Фиксированный шаг симуляции

Рендер и логика разведены по частоте (main.cpp):

```cpp
const float DT = 1.f / 60.f;   // шаг логики всегда 1/60 с
float acc = 0.f;
acc += GetFrameTime();         // реальное время кадра
if (acc > 0.25f) acc = 0.25f;  // защита от "спирали смерти" после лага
while (acc >= DT) { game.tick(DT); acc -= DT; }
```

Игра логически всегда идёт шагами по 1/60 с, независимо от того, 60 или 144 FPS
на мониторе. Кламп `0.25f` не даёт симуляции "догонять" часы огромным числом
тиков после фриза.

## 3. Мир и координаты

| Константа (`Game`) | Значение | Смысл |
|---|---|---|
| `CELL` | 48 px | клетка строительной сетки |
| сетка | 48 × 48 клеток | карта 2304 × 2304 px (`MAP_PX`) |
| `BSIZE` | 96 px | здание занимает 2 × 2 клетки |

Мировые координаты — пиксели от левого верхнего угла карты. Камера `Camera2D`
из raylib даёт панорамирование и зум (0.45–2.5×). Мышь в мировые координаты
переводится через `GetScreenToWorld2D`.

Строительство привязано к клеткам: `canPlace(gx, gy)` проверяет границы
(клетка 0..46, т.к. здание 2×2) и пересечение с живыми зданиями
(AABB-проверка по осям: `|dx| < BSIZE && |dy| < BSIZE`).

Три семейства сущностей, каждое — POD-структура + параллельные таблицы статов.

|---|---|---|---|---|
| TownCenter (ратуша) | 600 | — (стартовая) | +1.2 еды | +6 |
| House (дом) | 120 | 25 дерева | — | +4 |
| Farm (ферма) | 80 | 35 дерева | +2 еды | — |
| Sawmill (лесопилка) | 100 | 50 дерева | +2.5 дерева | — |
| Mine (шахта) | 100 | 60 дерева, 10 золота | +1.8 золота | — |
| Barracks (казарма) | 250 | 100 дерева, 40 золота | — | — |
| Tower (башня) | 200 | 60 дерева, 25 золота | — | атака |

### Юниты (`Unit`, `UType`) — нанимаются в казарме (Q/W/E)

| Юнит | HP | Урон | Дальность | Скорость | Кулдаун | Цена (еда/золото) |
|---|---|---|---|---|---|---|
| Swordsman (мечник) | 65 | 9 | 26 (ближний) | 65 | 0.8 с | 20 / 10 |

Арбалетчик заблокирован до буста **Crossbow License**. Найм требует свободного
слота населения (`units.size() < popCap`). Юниты спавнятся со сдвигом возле
первой живой казармы и держатся около точки спавна (`anchor`), когда врагов нет.

### Враги (`Enemy`, `EType`)

| Враг | HP | Урон | Дальность | Скорость | Кулдаун | Радиус |
|---|---|---|---|---|---|---|
| Runner | 30 | 6 | 22 (ближний) | 75 | 0.9 с | 11 |
| Brute | 130 | 16 | 28 (ближний) | 42 | 1.4 с | 16 |
| Spitter (плюющийся) | 45 | 9 | 150 | 55 | 1.6 с | 12 |

Статы хранятся как параллельные C-массивы, проиндексированные `(int)type`

## 5. Игровой цикл и фазы (`Phase`)

```
Day ──(phaseTimer 35 с)──► Night ──(все враги убиты)──► Boost ──(applyBoost)──► Day ──► ...
 │                                                          │
 └────────── ратуша уничтожена ─────────► GameOver ◄────────┘
```

Порядок работы `Game::tick(dt)` (все шаги — каждый тик):

1. Если фаза `Boost`/`GameOver` — выход (мир "заморожен").
2. Декремент фазового таймера; по истечении дня — `startNight()`.
3. Пересчёт `popCap` (сумма `B_POP` по живым зданиям).
4. Экономика: каждое живое здание начисляет доход × соответствующий множитель буста × `dt`.
5. Регенерация юнитов (если буст Field Medics).
6. Построение **пространственной сетки** по юнитам и врагам (см. раздел 7).
7. Юниты: перенацеливание → сокращение дистанции → атака по кулдауну.
8. Башни: выстрел в ближайшего врага в радиусе 230 по кулдауну 0.9 с (урон 10).
9. Враги: перенацеливание (юнит или здание — ближайшее) → движение → атака;
   уничтожение здания помечает `alive = false`, ратуша переводит игру в `GameOver`.
10. Уборка погибших: `erase/remove_if` по `hp <= 0`, счётчик `enemiesKilled`.
11. Если ночь и врагов не осталось → фаза `Boost`, генерация 3 предложений.

### Волны (`startNight`)

- Численность: `count = 3 + wave * 3`.
- Скалирование: HP `× (1 + 0.10·(wave−1))`, урон `× (1 + 0.05·(wave−1))`.
- Состав: с 3-й волны Brute составляет `count/4`, с 5-й — Spitter `count/5`,
  остальное — Runner'ы.
- Спавн: случайная точка на одной из четырёх сторон карты.

### Бусты (10 штук, выбор 1 из 3 после волны)

| ID | Название | Эффект |
|---|---|---|
| 0 | Tower Masters | башни +35% урона (аддитивно к множителю) |
| 1 | Sharp Blades | юниты +20% урона |
| 2 | Sturdy Armor | юниты +25% max HP и мгновенный хил 25% |
| 3 | Lumber Industry | +30% доход дерева |
| 4 | Rich Harvest | +30% доход еды |
| 5 | Gold Rush | +30% доход золота |
| 6 | War Economy | юниты на 20% дешевле |
| 7 | Crossbow License | открывает арбалетчика |
| 8 | Field Medics | реген +2 HP/с у юнитов |
| 9 | Spoils of War | мгновенно +120 дерева, +60 золота |

Выборка 3 уникальных ID — простой "выигрышный" алгоритм через массив `used[10]`.
Важная деталь баланса: Sturdy Armor **множит** `unitHpMult` и ретроактивно
баффает живых юнитов; доходные бусты **аддитивны** к множителю.

## 6. Ключевые приёмы в коде

### Таблицы статов через `enum class`

```cpp
enum class BType { TownCenter, House, Farm, Sawmill, Mine, Barracks, Tower, Count };
static const float B_HP[] = { 600.f, 120.f, 80.f, 100.f, 100.f, 250.f, 200.f };
// доступ: B_HP[(int)BType::Farm]
```

`enum class` не неявно конвертируется в `int` (типобезопасность), значения
явные, `Count` — удобная граница для циклов. Размер таблицы легко проверить
глазами: 7 значений на 7 типов.

### Стабильные индексы и уборка

Мёртвые сущности не удаляются мгновенно, а помечаются `alive = false` и
вычищаются пачкой в конце тика. Цели хранятся как **индексы** (`int target`),
поэтому важно валидировать их каждый тик (`u.target >= 0 && < size && alive`)
— соседние юниты могли убить цель раньше. Это дешевле, чем умные указатели
или хэндлы на этом масштабе, но требует дисциплины.

### Разделение «модель/представление»

`main.cpp` не знает правил игры — только вызывает `place/hire/applyBoost` и
читает поля `Game` для отрисовки. Вся логика принятия решений (можно ли
поставить, хватает ли ресурсов) живёт в `sim.cpp` и возвращает `bool`.

## 7. Пространственная сетка (uniform grid)

Поиск целей наивным перебором — O(n²): при 300 врагах и 100 юнитах это 30 000
проверок дистанции на тик. Вместо этого мир разбит на те же 48×48 клеток по
`CELL`, и в `tick` один раз строится сетка-индекс:

```cpp
struct Grid {
    std::vector<int> cells[48 * 48];   // индексы юнитов 0..n-1, врагов n..n+m-1
    void insert(float x, float y, int idx) { /* клетка = (x/CELL, y/CELL) */ }
};
```

Поиск ближайшего врага (`nearestEnemy`) смотрит только клетки внутри радиуса
поиска (`r = maxDist / CELL + 1`), что в среднем O(1) на запрос. Юниты и враги
различны смещением индекса на `units.size()`. Один нюанс: юниты ищут врагов
локально (радиус ≤ 900), а враги ищут цель глобально — при ближнем бою сетка
всё равно выигрывает, т.к. большинство проверок отсекается клеточно.

## 8. Самотест (`--selftest`)

Детерминированный прогон (`srand(12345)`): база из 9 зданий, 8 юнитов,
заваленные ресурсы → прогон до 3-й волны с авто-выбором первого буста.

Критерии PASS: поставлено ≥ 8 зданий, нанято ≥ 6 юнитов, применён ≥ 1 буст.
Текущий результат: `9/9 зданий, 8 юнитов, волна 3, 2 буста, 15 убийств — PASS`.

## 9. Сборка

`build.bat` (подробности и причины выбора MinGW — в корневом README):

```
g++ -std=c++20 -O2 -Wall -Wextra -mwindows -static
    -I third_party\raylib_mingw\include
    src\main.cpp src\sim.cpp
    -o bin\rts.exe
    third_party\raylib_mingw\lib\libraylib.a
    -static-libgcc -static-libstdc++
    -lwinmm -lgdi32 -lopengl32 -luser32 -lshell32
```

- `-O2` — оптимизация; `-Wall -Wextra` — все предупреждения.
- `-mwindows` — без консоли у готового exe (но и без stdout у самотеста — он
  используется вручную из терминала).
- raylib линкуется статически (`libraylib.a`), CRT тоже (`-static-lib*`) —
  exe один, зависимостей нет.

## 10. Что сознательно НЕ сделано (и почему)

- **Спрайты** — примитивы (прямоугольники/кружки), т.к. MVP: сначала играбельность, потом арт. Заложено: атлас + `DrawTexturePro`/инстансинг для тысяч юнитов.
- **Separation юнитов** — юниты могут наслаиваться; это осознанный долг.
- **Звук** — не подключён (miniaudio есть в raylib).
- **Сохранения** — состояние живёт только в памяти процесса.
- **Путь врагов** — движение напрямую к цели без обхода препятствий (здания не мешают движению).
