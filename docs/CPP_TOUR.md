# Экскурс в C++ по коду RTSurvivor

Это не учебник «в вакууме», а экскурс по **настоящему коду проекта** (~690 строк).
Каждый раздел — концепция языка + место, где она реально используется.
Читай с открытыми `src/sim.h` и `src/sim.cpp` рядом.

---

## 0. Как вообще устроена C++-программа

Программа начинается с функции `main` (main.cpp:87). Всё остальное — функции и
структуры, которые `main` вызывает. Компилятор (`g++`) превращает текст в exe.

У проекта два «этажа»:

- **`sim.h`** — заголовок: *объявления* (что существует). Здесь структуры
  `Vec2`, `Building`, `Game` и список методов `Game`.
- **`sim.cpp`** — *определения* (как это работает). Тела функций.
- **`main.cpp`** — `#include "sim.h"` и `#include "raylib.h"` — подключает
  объявления и пользуется ими.

`#pragma once` в первой строке заголовка — защита от двойного включения файла
(если два файла включат `sim.h`, содержимое вставится один раз). Это почти всё,
что нужно знать про препроцессор на старте.

## 1. Структуры: «свой тип данных»

В игре у всего есть позиция — пара чисел `x, y`. Вместо двух отдельных
переменных везде мы создали свой тип:

```cpp
struct Vec2 {
    float x = 0.f, y = 0.f;   // поля со значением по умолчанию
};
```

Теперь `Vec2 pos;` — одна переменная, `pos.x` — доступ к части.
`float` — дробное число одинарной точности (4 байта), `0.f` — литерал float
(без `.f` `0.0` был бы `double`).

Структуры бывают больше — `Building` собирает тип, позицию, здоровье, кулдаун:

```cpp
struct Building {
    BType type;
    Vec2 pos;              // центр, мировые координаты
    float hp, maxHp;
    float cooldown = 0.f;  // перезарядка атаки (башни)
    bool alive = true;
};
```

`bool` — правда/ложь. `= 0.f` и `= true` — **инициализация по умолчанию**:
если при создании не указать значение, оно будет таким. Это защита от мусора
в памяти.

## 2. Перегрузка операторов: пиши `a + b` как в математике

```cpp
struct Vec2 {
    Vec2 operator+(const Vec2& o) const { return { x + o.x, y + o.y }; }
    Vec2 operator-(const Vec2& o) const { return { x - o.x, y - o.y }; }
    Vec2 operator*(float s) const { return { x * s, y * s }; }
};
```

Это функции с необычными именами: когда компилятор видит `a + b`, где `a` —
`Vec2`, он вызывает `a.operator+(b)`. Благодаря этому движение юнита читается
как формула (sim.cpp:303):

```cpp
u.pos = u.pos + norm(e.pos - u.pos) * U_SPEED[(int)u.type] * dt;
// «позиция += направление × скорость × время»
```

Разбор модификаторов:
- `const Vec2& o` — **ссылка на константу**: аргумент передаётся без копирования
  (экономия), а `const` обещает: функция не изменит `o`. Для структур так пишут всегда.
- `const` после скобок — обещание «метод не меняет сам объект».

## 3. Функции: значение, ссылки, inline

```cpp
inline float len(Vec2 v) { return sqrtf(v.x * v.x + v.y * v.y); }
inline Vec2 norm(Vec2 v) { float l = len(v); return l > 0.0001f ? v * (1.f / l) : Vec2{ 0, 0 }; }
```

- `inline` — подсказка компилятору «вставь тело вместо вызова». Для крошечных
  функций — только выигрыш.
- `sqrtf` — квадратный корень из `<cmath>` (версия для float; обычный `sqrt` — для double).
- `условие ? a : b` — **тернарный оператор**: «если условие, то a, иначе b».
- Нормализация вектора: деление на длину. Проверка `l > 0.0001f` защищает от
  деления на ноль (нормализовать нулевой вектор нельзя — получили бы NaN).

Обрати внимание: `norm` возвращает **новый** Vec2, входной не меняет —
старые добрые функции без побочных эффектов.

## 4. `enum class`: перечисления без дыр в типах

```cpp
enum class BType { TownCenter, House, Farm, Sawmill, Mine, Barracks, Tower, Count };
enum class Phase { Day, Night, Boost, GameOver };
```

Это именованные константы: `BType::Farm` вместо «магической двойки».
`enum class` (в отличие от старого `enum`) **не превращается в int молча** —
нельзя случайно сложить ферму с фазой игры. Когда нужен номер — приводим явно:

```cpp
B_HP[(int)BType::Farm]   // 80
```

Трюк с `Count`: это последний элемент = количество вариантов. Циклы по всем
типам зданий пишутся так (main.cpp:137):

```cpp
for (int i = 0; i < (int)BType::Count; i++)   // i = 0..6
```

Добавил новое здание в enum и в таблицы — циклы подхватят его сами.

## 5. Таблицы данных: массивы параллельно enum'у

Симуляция не хранит статы в объектах — она хранит **таблицы**:

```cpp
static const float B_HP[]   = { 600.f, 120.f, 80.f, 100.f, 100.f, 250.f, 200.f };
static const float B_WOOD[] = { 0, 25, 35, 50, 60, 100, 60 };
```

- `static` у глобальной переменной в .cpp — видна только в этом файле
  (не засоряет другие единицы трансляции).
- `const` — менять нельзя, лежит в памяти как константа.
- Порядок значений = порядок в `enum`. Это компактно, кэш-дружественно
  (все HP идут подряд в памяти) и наглядно.

Оборачивающие функции `bName()`, `bCostWood()` и т.п. — это **API поверх таблиц**:
если завтра статы переедут в файлы конфигурации, вызовы в коде не изменятся.

## 6. `std::vector`: динамический массив

Игровой мир — три списка переменной длины:

```cpp
std::vector<Building> buildings;
std::vector<Unit> units;
std::vector<Enemy> enemies;
```

`std::vector` — массив, который растёт сам: `push_back(obj)` добавляет в конец,
`size()` — сколько элементов, `units[i]` — доступ как у массива.
Юнит рождается → `units.push_back(u)`; юнит умер → элемент вычищается
(см. следующий раздел).

Почему не обычный массив `Unit units[100]`? Потому что заранее неизвестно,
сколько будет юнитов, а вектор управляет памятью сам и при переполнении
увеличивается (обычно удваивая ёмкость).

## 7. Удаление элементов: remove_if + лямбда

В конце каждого тика погибших вычищают пачкой (sim.cpp:354):

```cpp
enemies.erase(std::remove_if(enemies.begin(), enemies.end(),
    [](const Enemy& e) { return e.hp <= 0.f; }), enemies.end());
```

Двухэтапная схема:
1. `std::remove_if(begin, end, предикат)` — переставляет «живых» в начало и
   возвращает итератор на новый конец («мёртвые» хвостом).
2. `erase(newEnd, end)` — реально стирает хвост.

`[](const Enemy& e) { return e.hp <= 0.f; }` — **лямбда**: безымянная функция
прямо на месте. Квадратные скобки — список захвата (здесь пустой: ничего из
окружения не нужно). Если нужны внешние переменные — пишем `[&]` (захват всего
по ссылке), как в `spawnOne` (sim.cpp:191).

Альтернатива «удалять в цикле по одному» — медленная и кишит багами со сдвигом
индексов. Так не пишут.

## 8. Ссылки: `auto&` и работа «на месте»

```cpp
for (auto& b : buildings)          // b — ссылка на Building в векторе
    if (b.alive) popCap += B_POP[(int)b.type];
```

`auto& b` читается как «b — то же самое здание, не копия». Изменения `b`
изменяют вектор. Если написать просто `auto b` — сделалась бы копия на каждой
итерации: медленно и бессмысленно.

Другой пример — атака по индексу цели (sim.cpp:294):

```cpp
auto& e = enemies[u.target];       // псевдоним элемента
e.hp -= U_DMG[(int)u.type] * unitDmgMult;   // урон реально записывается в вектор
```

Здесь видно связку раздела 4: цель хранится как `int target` (индекс), и каждый
тик её валидируют (`target >= 0 && target < size && alive`), потому что враг
мог умереть чуть раньше в этом же тике.

## 9. Методы и состояние: `struct Game` как «мир в одном объекте»

`Game` — большая структура, держащая всё состояние партии: ресурсы, фазу,
множители бустов, векторы сущностей. Рядом — **методы** (функции-члены):

```cpp
bool canAfford(BType t) const;                 // хватает ли ресурсов?
bool place(BType t, int gx, int gy);           // поставить здание (спишет ресурсы)
void tick(float dt);                           // один шаг мира
```

Соглашение про `const`: методы, не меняющие состояние (`canAfford`,
`canPlace`), помечены `const` — компилятор не даст их вызвать «на изменение»,
и читающий код сразу видит: «это вопрос, а не действие».

`reset()` (sim.cpp:74) использует любопытный приём:

```cpp
*this = Game();   // присвоить объекту свежесозданное значение по умолчанию
```

Новая игра за одну строчку: все поля обнуляются, векторы очищаются, затем
код ставит стартовую ратушу.

## 10. Время и игра «по кадрам»

Игры не «спят и ждут», они крутят цикл: **ввод → обновление → отрисовка**
(main.cpp:113). Всё в мире движется пропорционально `dt` — времени с
последнего кадра:

```cpp
phaseTimer -= dt;                                    // тикают часы дня
u.pos = u.pos + norm(e.pos - u.pos) * SPEED * dt;    // скорость × время = смещение
wood  += income * woodMult * dt;                     // доход в секунду × dt секунд
```

Поскольку кадры идут с разной скоростью, симуляцию стабилизируют
**фиксированным шагом** (раздел «Фиксированный шаг» в TECHNICAL.md): логика
всегда идёт шагами по 1/60 с, а `acc` накапливает «долг» реального времени.

## 11. Вспомогательные механизмы

```cpp
namespace { ... }        // безымянное пространство имён: Grid видна только в sim.cpp
constexpr int GCELLS = 48;  // константа времени компиляции (настоящий литерал, не переменная)
static const float TOWER_RANGE = 230.f;
```

- `namespace {}` — ещё один способ спрятать детали реализации.
- `constexpr` — «вычисли это при компиляции». Для размеров сетки это бесплатно.
